## Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Слой коммуникации

Для взаимодействия с сервером используется класс `WebLarekApi`, который инкапсулирует логику отправки HTTP-запросов. Он использует композицию с классом `Api` для выполнения запросов.

- Метод `getProducts()` выполняет GET-запрос на эндпоинт `/product/` и возвращает массив товаров типа `IProduct[]`.
- Метод `sendOrder(data: IOrderData)` выполняет POST-запрос на эндпоинт `/order/`, отправляя данные заказа и возвращает ответ сервера типа `IOrderResponse`.

Класс принимает в конструктор объект, реализующий интерфейс `IApi`, и использует его методы `get` и `post` для коммуникации с сервером.

Типы данных для коммуникации описаны в файле `src/types/index.ts`. Для описания формата заказа и ответа используются уже существующие типы `IProduct`, `IBuyer`, а также новые типы `IOrderData` и `IOrderResponse`, построенные на их основе.

## Данные
В приложении используются две основные сущности данных: товар и покупатель. Они описываются следующими интерфейсами TypeScript. Эти интерфейсы обеспечивают типизацию данных, что помогает в поддержке кода и предотвращении ошибок.

### Интерфейс IProduct
Описывает структуру данных для товара в магазине. Используется для хранения информации о товарах, полученных от сервера, и для передачи данных между компонентами приложения.

interface IProduct {
  id: string; - Уникальный идентификатор товара
  description: string; - Описание товара
  image: string; - Ссылка на изображение товара
  title: string; - Название товара
  category: string; - Категория товара
  price: number | null; - Цена товара (может быть null, если товар бесплатный)
}

### Интерфейс IBuyer
Описывает структуру данных для покупателя. Используется для хранения информации о пользователе при оформлении заказа, включая способ оплаты и контактные данные.

type TPayment = 'card' | 'cash'; - Тип для способа оплаты

interface IBuyer {
  payment: TPayment; - Способ оплаты
  email: string; - Email покупателя
  phone: string; - Телефон покупателя
  address: string; - Адрес доставки
}

Модели данных
Модели данных отвечают за хранение и управление данными в приложении. Они следуют принципам объектно-ориентированного программирования: каждый класс имеет единственную ответственность, изолирован и масштабируем. Модели взаимодействуют с другими частями приложения через события, генерируемые EventEmitter.

### Класс Catalog
Назначение и зона ответственности: Класс отвечает за хранение и управление данными о товарах в каталоге. Он предоставляет методы для сохранения, получения и поиска товаров, а также для управления выбранным товаром для подробного отображения.

Конструктор:
constructor() - Конструктор не принимает параметров и инициализирует пустые массивы для хранения данных.

Поля класса:
_items: IProduct[] - Массив всех товаров в каталоге. Хранит объекты типа IProduct и отвечает за полный список доступных товаров.
_preview: IProduct | null - Текущий товар, выбранный для подробного отображения. Хранит объект типа IProduct или null, если товар не выбран. Отвечает за хранение товара, который пользователь хочет просмотреть детально.

Методы класса:
setItems(items: IProduct[]): void - Сохраняет массив товаров, полученный в параметре items типа IProduct[], в поле _items. Не возвращает значения.
getItems(): IProduct[] - Возвращает массив всех товаров из поля _items типа IProduct[].
getItem(id: string): IProduct | undefined - Принимает параметр id типа string (идентификатор товара). Возвращает товар типа IProduct, если найден, или undefined, если товар не найден.
setPreview(item: IProduct): void - Сохраняет товар, полученный в параметре item типа IProduct, в поле _preview для подробного отображения. Не возвращает значения.
getPreview(): IProduct | null - Возвращает текущий товар для подробного отображения типа IProduct или null, если товар не выбран.

### Класс Basket
Назначение и зона ответственности: Класс отвечает за хранение и управление данными о товарах в корзине покупателя. Он предоставляет методы для добавления, удаления товаров, расчета стоимости и проверки наличия товаров.

Конструктор:
constructor() - Конструктор не принимает параметров и инициализирует пустой массив для хранения товаров в корзине.

Поля класса:
_items: IProduct[] - Массив товаров, выбранных покупателем для покупки. Хранит объекты типа IProduct и отвечает за список товаров в корзине.

Методы класса:
getItems(): IProduct[] - Возвращает массив товаров в корзине типа IProduct[].
addItem(item: IProduct): void - Добавляет товар, полученный в параметре item типа IProduct, в массив _items. Не возвращает значения.
removeItem(item: IProduct): void - Удаляет товар, полученный в параметре item типа IProduct, из массива _items. Не возвращает значения.
clear(): void - Очищает массив _items, удаляя все товары из корзины. Не возвращает значения.
getTotal(): number - Рассчитывает и возвращает общую стоимость всех товаров в корзине типа number (сумма цен товаров).
getCount(): number - Возвращает количество товаров в корзине типа number.
hasItem(id: string): boolean - Проверяет наличие товара по его идентификатору, полученному в параметре id типа string. Возвращает true, если товар найден, или false в противном случае.

### Класс Buyer
Назначение и зона ответственности: Класс отвечает за хранение и управление данными о покупателе. Он предоставляет методы для сохранения, получения, очистки и валидации данных покупателя.

Конструктор:
constructor() - Конструктор не принимает параметров и инициализирует пустые поля для данных покупателя.

Поля класса:
_payment: TPayment | null - Способ оплаты покупателя. Хранит значение типа TPayment или null, если не указано. Отвечает за хранение выбранного способа оплаты.
_email: string - Email покупателя. Хранит строку типа string. Отвечает за хранение контактного email.
_phone: string - Телефон покупателя. Хранит строку типа string. Отвечает за хранение контактного телефона.
_address: string - Адрес доставки покупателя. Хранит строку типа string. Отвечает за хранение адреса доставки.

Методы класса:
setPayment(payment: TPayment): void - Сохраняет способ оплаты, полученный в параметре payment типа TPayment, в поле _payment. Не возвращает значения.
setEmail(email: string): void - Сохраняет email, полученный в параметре email типа string, в поле _email. Не возвращает значения.
setPhone(phone: string): void - Сохраняет телефон, полученный в параметре phone типа string, в поле _phone. Не возвращает значения.
setAddress(address: string): void - Сохраняет адрес, полученный в параметре address типа string, в поле _address. Не возвращает значения.
getBuyerData(): IBuyer - Возвращает все данные покупателя в виде объекта типа IBuyer, собирая их из полей класса.
clear(): void - Очищает все поля данных покупателя, устанавливая их в начальные значения. Не возвращает значения.
validateOrder(): Record<string, string> - Проверяет способ оплаты и адрес; возвращает объект ошибок по полям (пустой объект, если ошибок нет).
validateContacts(): Record<string, string> - Проверяет email и телефон; возвращает объект ошибок по полям.
validate(): Record<string, string> - Объединяет ошибки validateOrder и validateContacts.

## Слой представления (View)

Слой View отвечает за отображение интерфейса и взаимодействие с DOM. Каждый класс View наследуется от абстрактного базового класса `Component<T>` и соответствует конкретному блоку разметки, инкапсулируя логику работы с этим блоком. Базовый класс `Component<T>` предоставляет контейнер и утилиты для рендеринга. Метод `render(data?: Partial<T>)` присваивает переданные данные в свойства объекта и возвращает корневой DOM-элемент. В дочерних классах `render` можно переопределять для дополнительной логики или использовать как есть, дополняя другими методами. Все классы используют утилиты базового класса, такие как `setImage` для изображений.

### Класс Header (наследуется от Component<IHeaderData>)

Отвечает за отображение и поведение шапки сайта, в частности, значка корзины с количеством товаров.

- **Наследование:** `Component<IHeaderData>` (где `IHeaderData` — интерфейс с полями вроде `count: number`).
- **Корневой элемент:** `.header` (передается в конструктор базового класса как `container`).
- **Основные элементы:** (инициализируются в дочернем классе, например, через `querySelector`).
  - Кнопка корзины (`headerButton`) — элемент с классом `.header__basket`.
  - Счетчик товаров (`counter`) — элемент с классом `.header__basket-counter`.
- **Функционал:**
  - Отслеживает клики по кнопке корзины и вызывает коллбек открытия модального окна корзины.
  - Обновляет значение счетчика при изменении количества товаров.
- **Пример методов:**
  - `render(data?: Partial<IHeaderData>): HTMLElement` — переопределяет базовый `render`, присваивает данные (например, `count`) и обновляет DOM (например, устанавливает текст счетчика). Возвращает `container`.
  - `setCount(count: number): void` — обновляет отображаемое число в счетчике путем изменения текста элемента `counter`.
  - `onBasketClick(callback: () => void): void` — подписка на клик по кнопке корзины (использует стандартный `addEventListener`).

### Класс Gallery (наследуется от Component<IGalleryData>)

Отвечает за отображение каталога товаров — контейнер для карточек товаров.

- **Наследование:** `Component<IGalleryData>` (где `IGalleryData` — интерфейс с полями вроде `items: HTMLElement[]`).
- **Корневой элемент:** `<main class="gallery">` (передается в конструктор как `container`).
- **Функционал:**
  - Отрисовывает список карточек товаров.
  - Управляет очисткой и обновлением содержимого галереи.
- **Пример методов:**
  - `render(data?: Partial<IGalleryData>): HTMLElement` — переопределяет базовый `render`, присваивает данные и вставляет карточки в `container` (например, используя `appendChild` или `replaceChildren` для обновления списка). Возвращает `container`.
  - `renderItems(items: HTMLElement[]): void` — отрисовывает переданные карточки товаров, вставляя их в `container`.
  - `clear(): void` — очищает содержимое галереи (например, `this.container.replaceChildren()`).

### Класс Modal (наследуется от Component<IModalData>)

Отвечает за отображение модального окна.

- **Наследование:** `Component<IModalData>` (где `IModalData` — интерфейс с полями вроде `content: HTMLElement`).
- **Корневой элемент:** `.modal__container` (передается в конструктор как `container`).
- **Особенности:** Класс не наследуется другими классами. Вся разметка внутри модального окна реализуется отдельными компонентами.
- **Основные элементы:** (инициализируются в дочернем классе).
  - Кнопка закрытия (`closeButton`) — элемент с классом `.modal__close`.
  - Контейнер контента (`content`) — элемент с классом `.modal__content`.
- **Функционал:**
  - Открытие и закрытие модального окна.
  - Вставка и замена контента в контейнере.
- **Пример методов:**
  - `render(data?: Partial<IModalData>): HTMLElement` — переопределяет базовый `render`, присваивает данные и вставляет контент в `content`. Возвращает `container`.
  - `open(): void` — открывает модальное окно (добавляет класс активного состояния к `container`).
  - `close(): void` — закрывает модальное окно.
  - `setContent(element: HTMLElement): void` — устанавливает контент в контейнер `content` (например, `this.content.replaceChildren(element)`).
  - `onClose(callback: () => void): void` — подписка на клик по кнопке закрытия.

### Родительский класс Card (наследуется от Component<IProduct>)

Общий базовый класс для всех типов карточек (каталог, предпросмотр, корзина).

- **Наследование:** `Component<IProduct>` (где `IProduct` — интерфейс с данными товара).
- **Назначение:** Инкапсулирует общий функционал работы с карточками (например, клонирование шаблона, заполнение базовых данных). Использует `setImage` из базового класса для изображений.
- **Общие методы:**
  - `render(data?: Partial<IProduct>): HTMLElement` — переопределяет базовый `render`, присваивает данные товара и заполняет DOM (например, устанавливает текст и изображения через `setImage`). Возвращает `container`.
  - В дочерних классах реализуются специфичные методы и шаблоны.

### Классы карточек товаров (наследники Card, а значит и Component<IProduct>)

1. **CardCatalog** — карточка товара для отображения в каталоге  
   - Использует шаблон `#card-catalog`.  
   - Отображает основную информацию о товаре в каталоге.  
   - **Пример методов:** `render(data?: Partial<IProduct>): HTMLElement` — присваивает данные и настраивает DOM для каталога (например, добавляет обработчик клика для открытия предпросмотра). Использует `setImage` для изображения.

2. **CardPreview** — карточка товара для подробного просмотра  
   - Использует шаблон `#card-preview`.  
   - Отображает расширенную информацию о товаре и кнопку добавления в корзину.  
   - **Пример методов:** `render(data?: Partial<IProduct>): HTMLElement` — присваивает данные и настраивает DOM для предпросмотра (например, использует `setImage` для большого изображения).

3. **CardBasket** — карточка товара в корзине  
   - Использует шаблон `#card-basket`.  
   - Отображает товар в компактном виде с кнопкой удаления из корзины.  
   - **Пример методов:** `render(data?: Partial<IProduct>): HTMLElement` — присваивает данные и настраивает DOM для корзины (например, добавляет индекс и кнопку удаления).

### Родительский класс Form (наследуется от Component<IFormData>)

Общий базовый класс для форм (заказа и контактов).

- **Наследование:** `Component<IFormData>` (где `IFormData` — интерфейс с данными формы, например, `payment: string`, `address: string`).
- **Назначение:** Инкапсулирует общий функционал работы с формами (валидация, управление состоянием кнопок, обработка событий).
- **Общие методы:**
  - `render(data?: Partial<IFormData>): HTMLElement` — переопределяет базовый `render`, присваивает данные формы и заполняет поля DOM. Возвращает `container`.
  - `setSubmitEnabled(enabled: boolean): void` — включает/выключает кнопку отправки путем изменения свойства `disabled`.

### Классы форм (наследники Form, а значит и Component<IFormData>)

1. **OrderForm** — форма для оформления заказа  
   - Использует шаблон `#order`.  
   - Отображает выбор способа оплаты и поле адреса.  
   - **Пример методов:** `render(data?: Partial<IFormData>): HTMLElement` — присваивает данные и настраивает DOM для формы заказа (например, устанавливает значение адреса и обрабатывает выбор оплаты).

2. **ContactsForm** — форма для ввода контактных данных  
   - Использует шаблон `#contacts`.  
   - Отображает поля для email и телефона.  
   - **Пример методов:** `render(data?: Partial<IFormData>): HTMLElement` — присваивает данные и настраивает DOM для формы контактов (например, устанавливает значения email и телефона).

### Класс Basket (наследуется от Component<IBasketData>)

Отвечает за отображение корзины товаров в модальном окне.

- **Наследование:** `Component<IBasketData>` (где `IBasketData` — интерфейс с полями вроде `items: IProduct[]`, `total: number`).
- **Корневой элемент:** Использует шаблон `#basket` для контейнера.
- **Основные элементы:** (инициализируются в дочернем классе).
  - Список товаров (`list`) — элемент с классом `.basket__list`.
  - Общая цена (`total`) — элемент с классом `.basket__price`.
  - Кнопка оформления (`button`) — элемент с классом `.basket__button`.
- **Функционал:**
  - Отрисовывает список товаров в корзине.
  - Обновляет общую стоимость.
  - Обрабатывает клик по кнопке оформления.
- **Пример методов:**
  - `render(data?: Partial<IBasketData>): HTMLElement` — переопределяет базовый `render`, присваивает данные и обновляет DOM (например, вставляет карточки товаров в список и устанавливает общую цену). Возвращает `container`.
  - `setTotal(total: number): void` — обновляет отображаемую общую стоимость.
  - `onOrderClick(callback: () => void): void` — подписка на клик по кнопке оформления.

### Класс Success (наследуется от Component<ISuccessData>)

Отвечает за отображение окна успешного оформления заказа.

- **Наследование:** `Component<ISuccessData>` (где `ISuccessData` — интерфейс с полями вроде `total: number`).
- **Корневой элемент:** Использует шаблон `#success` для контейнера.

  - Описание (`description`) — элемент с классом `.order-success__description`.
  - Кнопка закрытия (`closeButton`) — элемент с классом `.order-success__close`.
- **Функционал:**
  - Отображает сообщение об успешном заказе с общей суммой.
  - Обрабатывает клик по кнопке закрытия.
- **Пример методов:**
  - `render(data?: Partial<ISuccessData>): HTMLElement` — переопределяет базовый `render`, присваивает данные и обновляет DOM (например, устанавливает текст описания). Возвращает `container`.

  - `onCloseClick(callback: () => void): void` — подписка на клик по кнопке закрытия.

## События в приложении

События генерируются в классах View и используются для связи с Presenter (основной логикой). Каждый класс View может генерировать события через EventEmitter или вызывать коллбеки. Ниже список событий:

- **Header**:
  - `basket:open` — генерируется при клике по кнопке корзины. Уведомляет о необходимости открыть модальное окно корзины.

- **Gallery**:
  - Нет специфических событий (отображает данные, но не генерирует).

- **Modal**:
  - `modal:close` — генерируется при клике по кнопке закрытия. Уведомляет о необходимости закрыть модальное окно.

- **CardCatalog**:
  - `card:catalog:select` — генерируется при клике по карточке товара в каталоге. Передает `{ id: string }`.

- **CardPreview**:
  - `card:preview:add` — генерируется при клике по кнопке корзины. Передает `{ id: string }`. Состояние «в корзине» передаётся в `render` флагом `inBasket` (View не знает о модели Basket).

- **CardBasket**:
  - `card:basket:remove` — генерируется при клике по кнопке удаления. Передает `{ id: string }`.

- **OrderForm**:
  - Нет прямых событий (использует 'form:order:change' для уведомлений о изменениях).

- **ContactsForm**:
  - `form:contacts:change` — генерируется при вводе в поля email или телефона. Передает обновленные данные.

- **Basket**:
  - `basket:order` — генерируется при клике по кнопке оформления. Уведомляет о необходимости перейти к заказу.

- **Success**:
  - `success:close` — генерируется при клике по кнопке закрытия. Уведомляет о необходимости закрыть окно успеха.

## Презентер

Презентер в приложении реализован в файле `main.ts`. Он выступает связующим звеном между моделями и представлениями, обеспечивая их взаимодействие через единый событийный брокер `EventEmitter`.

### Основные функции презентера:

- **Инициализация моделей и представлений:**
  - Создаёт модели каталога (`Catalog`), корзины (`Basket`) и покупателя (`Buyer`), передавая им общий событийный брокер.
  - Создаёт View-компоненты (`Header`, `Gallery`, `Modal`, карточки товаров, формы заказа и контактов, корзина и окно успеха), передавая им контейнеры DOM и событийный брокер.

- **Обработка событий:**
  - Подписывается на события от моделей и представлений, такие как изменения каталога, предпросмотра, корзины, данных покупателя и действий пользователя.
  - Реагирует на эти события, обновляя интерфейс: рендерит карточки товаров, открывает и закрывает модальные окна, обновляет содержимое корзины и форм.
  - Управляет состоянием модального окна (открыто корзина, форма заказа, окно успеха или предпросмотр) с помощью внутренних флагов.

- **Создание элементов интерфейса:**
  - Содержит вспомогательные функции для создания карточек каталога, предпросмотра и корзины из шаблонов с передачей данных.
  - Обеспечивает актуализацию отображения корзины и счётчика товаров в шапке.

- **Управление формами заказа и контактов:**
  - Обрабатывает изменения в формах, обновляя данные покупателя.
  - Проверяет валидность форм и включает/отключает кнопку отправки.
  - Отправляет заказ на сервер через API, обрабатывает ответ и отображает окно успеха.
  - После успешного заказа очищает корзину и данные покупателя.

- **Поддержание разделения ответственности:**
  - Презентер не генерирует собственных событий — он только подписывается и реагирует на события, обеспечивая чистую архитектуру.
  - Логика отображения и управления состоянием сосредоточена именно здесь, что облегчает поддержку и развитие приложения.

Таким образом, презентер в `main.ts` выполняет роль «дирижёра», координируя взаимодействие всех компонентов, обеспечивая синхронизацию данных и интерфейса, а также плавный пользовательский опыт в приложении «Веб-Ларёк».
