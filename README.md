# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Webpack

Структура проекта:
- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами
- src/components/base/ — папка с базовым кодом

Важные файлы:
- index.html — HTML-файл главной страницы
- src/types/index.ts — файл с типами
- src/main.ts — точка входа приложения

- src/utils/constants.ts — файл с константами
- src/utils/utils.ts — файл с утилитами

## Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Слой коммуникации

Для взаимодействия с сервером используется класс `WebLarekApi`, который инкапсулирует логику отправки HTTP-запросов. Он использует композицию с классом `Api` для выполнения запросов.

- Метод `getProducts()` выполняет GET-запрос на эндпоинт `/product/` и возвращает массив товаров типа `IProduct[]`.
- Метод `sendOrder(data: IOrderData)` выполняет POST-запрос на эндпоинт `/order/`, отправляя данные заказа и возвращает ответ сервера типа `IOrderResponse`.

Класс принимает в конструктор объект, реализующий интерфейс `IApi`, и использует его методы `get` и `post` для коммуникации с сервером.

Типы данных для коммуникации описаны в файле `src/types/index.ts`. Для описания формата заказа и ответа используются уже существующие типы `IProduct`, `IBuyer`, а также новые типы `IOrderData` и `IOrderResponse`, построенные на их основе.

## Данные
В приложении используются две основные сущности данных: товар и покупатель. Они описываются следующими интерфейсами TypeScript. Эти интерфейсы обеспечивают типизацию данных, что помогает в поддержке кода и предотвращении ошибок.

### Интерфейс IProduct
Описывает структуру данных для товара в магазине. Используется для хранения информации о товарах, полученных от сервера, и для передачи данных между компонентами приложения.

### Интерфейс IBuyer
Описывает структуру данных для покупателя. Используется для хранения информации о пользователе при оформлении заказа, включая способ оплаты и контактные данные.

Модели данных
Модели данных отвечают за хранение и управление данными в приложении. Они следуют принципам объектно-ориентированного программирования: каждый класс имеет единственную ответственность, изолирован и масштабируем. Модели взаимодействуют с другими частями приложения через события, генерируемые EventEmitter.

### Класс Catalog
Назначение и зона ответственности: Класс отвечает за хранение и управление данными о товарах в каталоге. Он предоставляет методы для сохранения, получения и поиска товаров, а также для управления выбранным товаром для подробного отображения.

Конструктор:
constructor() - Конструктор не принимает параметров и инициализирует пустые массивы для хранения данных.

Поля класса:
_items: IProduct[] - Массив всех товаров в каталоге. Хранит объекты типа IProduct и отвечает за полный список доступных товаров.
_preview: IProduct | null - Текущий товар, выбранный для подробного отображения. Хранит объект типа IProduct или null, если товар не выбран. Отвечает за хранение товара, который пользователь хочет просмотреть детально.

Методы класса:
setItems(items: IProduct[]): void - Сохраняет массив товаров, полученный в параметре items типа IProduct[], в поле _items. Не возвращает значения.
getItems(): IProduct[] - Возвращает массив всех товаров из поля _items типа IProduct[].
getItem(id: string): IProduct | undefined - Принимает параметр id типа string (идентификатор товара). Возвращает товар типа IProduct, если найден, или undefined, если товар не найден.
setPreview(item: IProduct): void - Сохраняет товар, полученный в параметре item типа IProduct, в поле _preview для подробного отображения. Не возвращает значения.
getPreview(): IProduct | null - Возвращает текущий товар для подробного отображения типа IProduct или null, если товар не выбран.

### Класс Basket
Назначение и зона ответственности: Класс отвечает за хранение и управление данными о товарах в корзине покупателя. Он предоставляет методы для добавления, удаления товаров, расчета стоимости и проверки наличия товаров.

Конструктор:
constructor() - Конструктор не принимает параметров и инициализирует пустой массив для хранения товаров в корзине.

Поля класса:
_items: IProduct[] - Массив товаров, выбранных покупателем для покупки. Хранит объекты типа IProduct и отвечает за список товаров в корзине.

Методы класса:
getItems(): IProduct[] - Возвращает массив товаров в корзине типа IProduct[].
addItem(item: IProduct): void - Добавляет товар, полученный в параметре item типа IProduct, в массив _items. Не возвращает значения.
removeItem(item: IProduct): void - Удаляет товар, полученный в параметре item типа IProduct, из массива _items. Не возвращает значения.
clear(): void - Очищает массив _items, удаляя все товары из корзины. Не возвращает значения.
getTotal(): number - Рассчитывает и возвращает общую стоимость всех товаров в корзине типа number (сумма цен товаров).
getCount(): number - Возвращает количество товаров в корзине типа number.
hasItem(id: string): boolean - Проверяет наличие товара по его идентификатору, полученному в параметре id типа string. Возвращает true, если товар найден, или false в противном случае.

### Класс Buyer
Назначение и зона ответственности: Класс отвечает за хранение и управление данными о покупателе. Он предоставляет методы для сохранения, получения, очистки и валидации данных покупателя.

Конструктор:
constructor() - Конструктор не принимает параметров и инициализирует пустые поля для данных покупателя.

Поля класса:
_payment: TPayment | null - Способ оплаты покупателя. Хранит значение типа TPayment или null, если не указано. Отвечает за хранение выбранного способа оплаты.
_email: string - Email покупателя. Хранит строку типа string. Отвечает за хранение контактного email.
_phone: string - Телефон покупателя. Хранит строку типа string. Отвечает за хранение контактного телефона.
_address: string - Адрес доставки покупателя. Хранит строку типа string. Отвечает за хранение адреса доставки.

Методы класса:
setPayment(payment: TPayment): void - Сохраняет способ оплаты, полученный в параметре payment типа TPayment, в поле _payment. Не возвращает значения.
setEmail(email: string): void - Сохраняет email, полученный в параметре email типа string, в поле _email. Не возвращает значения.
setPhone(phone: string): void - Сохраняет телефон, полученный в параметре phone типа string, в поле _phone. Не возвращает значения.
setAddress(address: string): void - Сохраняет адрес, полученный в параметре address типа string, в поле _address. Не возвращает значения.
getBuyerData(): IBuyer - Возвращает все данные покупателя в виде объекта типа IBuyer, собирая их из полей класса.
clear(): void - Очищает все поля данных покупателя, устанавливая их в начальные значения. Не возвращает значения.
validate(): boolean - Проверяет корректность данных покупателя (например, наличие всех обязательных полей и правильный формат email/телефона). Возвращает true, если данные валидны, или false в противном случае.
